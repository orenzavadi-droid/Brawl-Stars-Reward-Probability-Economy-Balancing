# Red Team — would a Game Economy lead take this seriously?

## Upfront verdict

**Useful as a tiny, defensible probability/economy-design case; not enough by itself to prove actual player psychology or production readiness.** The original idea (compare a guaranteed 100 to a loot box) was too generic and detached from the named game. This version anchors one input set in real, officially disclosed regular Starr Drop rarity odds and isolates one deliberate design change.

## Biggest possible objections and how this version handles them

1. **"These aren't the real rewards."** Correct. The *rarity probabilities* in A are the official published numbers; **all value units are invented**. Real rewards are mixed types and depend on eligibility, fallback grants and inventory. No claim of actual 108 Coins, dollars, game-cost or player value.
2. **"Did Supercell actually test this alternative?"** No. B is a new, invented concept. Never imply Supercell uses or endorses it.
3. **"Does equal EV mean equal operating cost?"** No. Equal EV on a made-up shadow value scale only. A production model would value each reward type and account segment and reconcile actual currency ledgers and reward inventory obligations.
4. **"Does more Rare mean players feel worse?"** **Not measured.** The project calculates probability of five consecutive *initial* Rare rarities, not emotion. A behavioral prediction is explicitly a hypothesis requiring consented playtests and randomized validation.
5. **"Can we call a ten-drop sequence retention or engagement?"** No. We calculate reward outcomes, not voluntary play frequency, retention, payer conversion or LTV.
6. **"Are these outcomes independent?"** We assume independent, identically distributed openings. The live game may have different states, protections, fallback effects, or event variants. Independency is a modeling simplification to be validated.
7. **"Could a huge Legendary be worthless to a veteran?"** Yes. Effective utility changes with collection state. A real trial needs pre-treatment segmentation by account ownership/tenure and item value.
8. **"Why look at the first five Rare results?"** It is an explicitly defined, intuitive illustration of consecutive low-tier outcomes. It's **not** the chance of *any* five-Rare run within ten drops; do not conflate them.
9. **"Would B be good for revenue?"** Unknown. The project models neither spending nor actual player engagement. Avoid recommending a live change.
10. **"Is rarity itself the reward value?"** No. Tier/rarity mix is only a proxy. All reward types and fallback odds need an item-level production model.
11. **"What about safety and fairness?"** Avoid using the design to exploit vulnerable players or create harmful purchase pressure. The exploratory playtest uses **free, virtual opens** and tests enjoyment/frustration, not spending compulsion.
12. **"Can I replay the math?"** Yes. One CSV; transparent exact formulas; unit tests and exact ten-drop convolution. No unreported Monte Carlo noise or hand-selected results.

## Improvement path — if a hiring manager asks for more

- Real inventory-weighted payout accounting by player stage, after permission/access to game data.
- 5–10 person **exploratory** hands-on non-paid playtest to learn how players describe their experience; not evidence of statistical significance.
- Registered player-level A/B with primary experience and/or voluntary return metrics, long-term economic guardrails, sufficient sample and fixed test window.

## Story discipline

Say **"the counterfactual predicts reward distributions, not player feelings"**, and present the project as *design judgment plus mathematical honesty*. This is a mechanism case, not an empirical psychological study.
